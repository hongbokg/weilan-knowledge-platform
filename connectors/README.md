# Codex、WorkBuddy 与飞牛 Octop

对外接入优先复用 WeKnora 的原生 Streamable HTTP MCP，或在授权业务 API 上增加薄适配层。不能直连向量数据库来绕过权限、版本过滤和审计。

1. 在 WeKnora 设置中创建只读 MCP 端点，只选择普通知识库和需要的检索工具。保险箱、审计资料、黑名单不纳入此端点。
2. 显式选择知识库范围；不要将空范围误当作无权限。客户端使用独立、可撤销的凭据。
3. 复制实际 HTTPS MCP URL；通常形如 `https://kb.example.com/mcp/ENDPOINT_ID`，以部署版本界面显示为准。
4. WorkBuddy 连接器添加 Streamable HTTP 地址，在私密配置中设置 `Authorization: Bearer <令牌>`。不同版本客户端配置形状可能不同，先测试初始化、工具发现、检索与拒绝案例。
5. Codex 在 MCP 设置添加同一 HTTPS 服务，使用单独令牌。不要将真实令牌填进本仓库示例。
6. 飞牛内 Octop 使用其自定义 MCP 连接器。它负责专家编排，WeKnora 负责正文、表格和目录检索；两者不共享数据库。NAS 端使用内网 HTTPS 地址与只读文件账号。

原生端点的工作区权限与员工权限不是天然等同；必须在本实例验证受限文档拒绝后才启用。本文提供接入契约，不表示任意第三方客户端已完成实际认证验收。

安装包没有复制旧 Codex 插件：旧插件适配的是早期平台 API，与当前 WeKnora 的路由不完全一致，避免重复工具或误接。

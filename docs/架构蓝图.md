# 架构蓝图

```mermaid
flowchart TD
 NAS[企业 NAS 只读 WebDAV] --> CAT[文件目录索引和同步台账]
 CAT --> HASH[MD5 SHA256 版本规划]
 HASH --> CPU[CPU 电子 PDF 和 Office]
 HASH --> GPU[MinerU 有界 GPU 推理池]
 CPU --> QC[正文 表格 坐标和凭据检查]
 GPU --> QC
 QC -->|失败| REPAIR[隔离和定向修复候选]
 REPAIR --> QC
 QC -->|合格| API[WeKnora manual 业务 API]
 API --> INDEX[关键词与本地 BGE-M3 索引]
 INDEX --> WEB[Web 与 Android]
 INDEX --> MCP[鉴权 API MCP]
 MCP --> AGENT[WorkBuddy Codex 飞牛 Octop]
 INDEX -->|按需| SUM[摘要缓存和重点项目 Wiki]
```

CPU 文档通道、文件发现队列、MinerU 区域请求队列、WeKnora 内部任务队列分别统计，不能混为一个 pending 数值。解析完成也不等于向量索引可查，最终状态通过业务 API 核对。

原件在 NAS；不可变内容归档、解析结果与检查点在本地归档盘；有界临时页面位于 noswap tmpfs。SQLite 是同步状态台账，WeKnora 使用其自身数据库和向量存储，两者不是互相替代。

当前图中的原生电子 PDF 与扫描页分流已实现，混合页面的逐区域 CPU/GPU 组合仍受质量验收开关约束。CPU 图片补识别是补救分支，不替换主要 GPU 表格识别。

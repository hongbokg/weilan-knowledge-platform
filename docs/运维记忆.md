# 运维记忆

该文件是交付所需的脱敏工程决策摘要，不是公司对话、NAS 内容或凭据的导出。

- NAS 原件是事实来源，增量流程只读读取，不移动或覆盖文件。
- 解析、目录发现、摘要与 Wiki 分开；优先正文和检索索引，Wiki 手动选择重点项目。
- 两路独立 GPU 上下文和文件通道是不同概念；文档通道可以一大三小，但实际推理仍受两路 admission 控制。
- 常驻视觉模型保留结构 token；更换后端需验证复杂表格，不能只比较速度。
- 表格识别、正文覆盖、坐标、密码隔离共同决定可否发布。低置信度结果留在修复台账。
- GPU 利用率不是成功指标；合格页速率、P95、等待与实际入库可检索性更重要。
- CPU 预取和 GPU 推理重叠，阶段墙钟不能简单相加；缺失指标为 null，不按零处理。
- Base64 PNG 编解码在一次实测中只占页耗时约 1.8%，共享内存不是已验证的主要提速项。
- 图片补识别采用独立 CPU Paddle 3.2.2 环境，保留三份本地模型，旋转坐标逆变换经过测试；主 GPU 环境不随之升级。
- 空摘要可能源于模型输出预算、推理 token、限流或接口返回，不等于 OCR 失败。有限重试、缓存、分类预算先于历史全量回填。
- HY3 摘要、GLM 重点合成和 App 回答模型分别配置。任何“免费”“不限量”说法不替代实际供应商配额核查。
- 模型建议不能直接执行 shell。关闭服务前保存检查点，开机重新加载模型并续跑任务，不保存 CUDA 进程内存。
- 跨客户端访问使用可撤销凭据和业务 API，不直连数据库绕过权限。新公司或新项目资料必须验证归属。

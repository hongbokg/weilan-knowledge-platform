# 蔚蓝知识库平台介绍与特色

## 平台定位

蔚蓝知识库平台面向企业 NAS 中长期积累的招投标、项目技术、公司资质和历史报价资料。它持续发现文件、识别内容、建立检索索引，并保存原文件位置，使员工能够从问题、公司、项目、产品型号等入口查找资料，再回到 NAS 核对原文。

员工沿用现有 NAS 文件管理方式。知识库通过只读账号读取获准目录，原件不被移动或覆盖；新文件和修改文件进入增量流程，解析异常单独处理。平台以 WeKnora 为知识与问答基础，增加了企业资料同步、CPU/GPU 分流、质量工作流、业务整理与运行监控能力。

## 面向业务的使用价值

**准备投标材料。** 按公司、项目及资料类型盘点证照、技术方案和历史投标材料。文件目录检索与正文检索互相补充，尚待解析的原件可以被发现；未命中时说明当前索引状态，不将“未召回”直接解释为“NAS 没有”。

**复用技术方案。** 从智慧园区、监控安防、全光网络、道闸、空调安装等工程资料中寻找相关内容，带来源起草技术文稿。生成结果仍需核对招标要求与原文，不能把历史案例视为当前项目的承诺。

**查询产品和历史报价。** 按产品型号、名称、参数及品类检索原表证据。结构化结果保留工作表、行列、单位、税率等信息；报价趋势用于参考，历史最低价不能直接当作当天采购成本。单位、税率或币种未知时，不强行合并价格区间。

**移动查阅与专家协作。** Android 客户端提供账号登录、知识问答、图片预览和原文件卡片。授权 API/MCP 可向 WorkBuddy、Codex、飞牛 Octop 提供检索工具，专家助手复用同一知识来源，而非另建一套不可追溯的文件副本。

## 平台特色

### 内容识别与目录发现共同工作

文件被扫描发现后先登记名称、路径、格式、修改时间和状态。正文、表格与图片识别完成后补充内容索引。目录可查与正文可查是不同状态，界面和接口保持这一差别，避免资料尚未解析就被误判不存在。

### 充分使用本地硬件并保留质量门槛

电子 PDF 的可靠文字和表格优先由 CPU 提取；扫描页、混合页及不确定结构交给 MinerU GPU。CPU 预取与 GPU 推理重叠运行，推理上下文常驻，等待队列和内存有上限。大文件逐页处理和保存进度，避免长期独占队列。

### 每份知识能够回查来源

保留内容哈希、原 NAS 路径、版本与实际定位。相同文件内容复用识别成果，多个来源位置仍可追溯。PDF 使用实际物理页码，Office 无可靠页码时使用段落或资产定位，缺失坐标不会被编造。

### 异常资料进入独立修复流程

识别不足、图片文字遗漏、超大页面和 Office 转换失败按原因分流，保留已成功识别部分。CPU PaddleOCR 可补充图片文字；低置信度和表格不能仅靠文字拼接放行。发现密码内容时保留管理员处理边界。

### 企业资料整理与产品证据相结合

根据明确目录整理公司和项目知识库，并提供独立产品、参数与历史报价记录。自动整理依赖明确证据，不能把另一家公司的审计资料当成目标公司的资料；含糊归属保持待确认。

### 运行进度可见且结果能够核验

展示 CPU、GPU、显存和内存变化，以及文件状态、合格页速率、等待时长和失败原因。断点任务在重新启动后继续处理。监护采用有限、可审计的策略，模型建议不会直接变成任意服务器命令。

## 技术组成

| 组件 | 主要任务 |
|---|---|
| WeKnora | 知识文档、检索、权限与问答入口 |
| CPU PDF 工具 | PDFium 页面渲染，PyMuPDF 原生文字与表格提取 |
| MinerU 与本地 GPU | 扫描文档版面、文字和表格识别 |
| AnyDoc 适配器 | CPU Office 文档转换与图片资产提取 |
| PaddleOCR | 图片文字遗漏的独立补识别 |
| Ollama 与 BGE-M3 | 本地文本向量化 |
| HY3 GLM 等云端模型 | 已识别文字的摘要和生成任务 |
| API MCP 与 Android 客户端 | 专家工具接入及移动查阅 |

## 当前能力边界

多页大 PDF 已支持分页和检查点；巨型单页图纸仍需专门切片、拼接与坐标验收。复杂表格、低置信度证照和错误原图关联仍可能进入复核。此次发布不承诺全格式完全正确，也不承诺全部历史资料已完成入库。

Wiki 对重点项目按需合成，摘要可复用缓存。云端模型是否可用、费率和配额以对应服务方及实际账号为准。客户端源码与接口测试不能替代真实手机、真实权限及第三方专家的完整验收。

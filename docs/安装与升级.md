# 安装与升级

## 安装包的范围

这是源码与 NAS 入库扩展安装包。安装器部署 `server/pipeline/src` 与四组 systemd 定时任务，不自动安装 WeKnora、PostgreSQL、向量数据库、GPU 驱动、模型权重、云端模型，也不自动修改 Nginx。其他模块保留源码及单独集成说明。

现有生产服务器不能直接运行 install。发现同名目录、配置或服务时，安装器拒绝覆盖；升级需按检查点、版本比对、备份和回退步骤进行。本轮打包不改变正在运行的生产配置。

## Linux 前提

1. Ubuntu 24.04、Python 3.12 与 `python3-venv`；CPU/GPU 模型服务已按自己的硬件部署。
2. 可用的 WeKnora 业务 API，预先创建普通目标知识库、绑定检索模型。云端摘要和 Wiki 不应随首次全量同步自动启用。
3. MinerU 4.0.8 jobs API，支持 `POST /v1/parse/jobs`、本地路径输入、Markdown 和 structured_content 输出，并对解析进程授予临时目录访问。其他 MinerU 版本须先验证此契约。
4. `/data/archive` 已挂载至归档文件系统，预留至少 20GiB，取得真实 UUID。安装器不分区、不格式化、不创建 LVM。
5. `/run/weknora-work` 是有容量上限的 tmpfs，必须包含 `noswap` 选项；只配置系统支持的大小。内核不支持 noswap 时不能绕过 guard。
6. NAS 使用只读账号和 HTTPS。私有 CA 可将 `nas_ca` 填为服务器可读的 CA 文件路径，不通过关闭证书验证解决连接问题。

## 新安装

```bash
sha256sum -c SHA256SUMS
python3 installer/install.py plan
sudo bash install.sh install
```

安装器校验 MANIFEST，创建专用运行目录与服务账号、安装 Python 依赖、生成定时任务。默认不开启任何任务。若依赖安装失败，请保存错误并清理本次未启用的安装或按说明补齐环境；不要强制覆盖现有目录。

归档目录权限为服务账号可读写，NAS 账号仅具备读取权限。准备正式配置时，复制 `/etc/weknora-nas-sync/config.example.json` 为 `config.json`，填写 NAS 地址、账号、密码、普通知识库 API key、目标库 ID、归档 UUID。保持服务账号属主和 `0600`，不要把配置作为 Issue 附件。

```bash
sudo /opt/weknora-nas-sync/.venv/bin/python installer/install.py preflight
sudo /opt/weknora-nas-sync/.venv/bin/python installer/install.py activate
systemctl status weknora-nas-sync-worker.timer
```

preflight 使用只读请求检查 NAS、知识库权限与 MinerU 路由，验证归档 UUID、noswap tmpfs 和余量，不创建知识。activate 才启用扫描、CPU 转换、文档准备、发布四组定时任务。实际小批解析和索引仍需验收，preflight 通过不等于全量链路已通过。

扫描服务每半小时唤醒 `scan-due`，由台账控制每三天执行一次完整增量盘点；其他任务完成后至少等待三十秒再次调度。

## Office CPU 转换

`server/anydoc-worker` 是与 WeKnora 固定 AnyDoc 依赖相配的独立 Go 适配器。以已有 WeKnora 源码中的 `third_party/anydoc-go` 构建；该第三方库及本地库链接依赖仍以 WeKnora 的构建说明为准。

```bash
cd server/anydoc-worker
go mod edit -replace github.com/firecrawl/anydoc/go=/opt/weknora/third_party/anydoc-go
go build -o anydoc-worker-bin .
sudo install -m 0755 anydoc-worker-bin /opt/weknora-nas-sync/anydoc-worker-bin
```

当前适配器 Office 单文件上限为 64MiB，180 秒转换超时；超限需要独立拆分和转换方案，不能宣传任意大 Office 文件都已支持。Excel 不进入这条 OCR 主队列，目录仍可发现，报价由独立产品模块处理。

## WeKnora 页面与模型补丁

`server/weknora-overlay` 含服务器现用源码补丁及新增 Go/Vue 文件，基础提交固定为 `9114e4e4f905be71976a77c684d3f92731e6f9a6`。在新的干净 checkout 里先检查，再应用，不直接作用于已有生产目录。

```bash
python3 installer/apply_weknora_overlay.py /path/to/clean/weknora
python3 installer/apply_weknora_overlay.py /path/to/clean/weknora --apply
```

应用后按上游步骤编译前后端，测试并部署。Monitor 后端位于 `server/pipeline/src/monitor.py`，应只监听回环；通过已有 HTTPS 网关转发 `/api/v1/system/admin/nas-monitor` 和 NAS 文件接口。沿用管理员与知识库鉴权。安全关机按钮还依赖既有受限关机 helper，本包未自动安装其 root 权限链，不能只复制页面就声明安全关机可用。

## GPU 与图片补识别

主 GPU 使用现有 MinerU 服务；可选双常驻上下文 relay 代码在 `vlm_pool.py` 与 `weknora_vlm_structured.py`，依赖见 relay-runtime.lock。不能在单上下文内部取消排他锁后宣称并发安全。不同硬件须按同批文档验证吞吐、表格和坐标，不能直接套用 A2 的参数。

图片补识别 service 模板只作为独立模块交付，默认不启用。CPU 环境须为 Paddle 3.2.2、PaddleOCR 3.7.0、PaddleX 3.7.2，且有三份指定本地模型目录。运行时锁不是完整离线依赖清单，需准备独立 venv 并通过启动校验后再启用。

## 自动分库与摘要

`server/organization` 和 `server/operations` 包含现用参考源码，尚有生产路径、管理员准备步骤与数据库契约；不属于通用安装器自动启用范围。不要直接在不同 schema 上执行 organize.py 或历史摘要回填。先审阅空间 ID、鉴权范围、预算、API 返回结构并做小批验收。`server/summary-assistant` 不包含云端 key 或 OpenClaw runtime。

## 升级和回退

保留现有源码、配置和 SQLite 在线备份，暂停自己的工作队列并等待页面检查点退出，核对当前版本和候选哈希；再复制已验收的模块。不要删除模型锁，不要泛杀 Python，不要用旧数据库覆盖持续更新台账。

回退首先停用本次新增 timer 或辅助补识别服务，保留 NAS、台账、已识别页和已发布知识。撤销已发布内容时必须按对应版本和业务 API 核对，不能只恢复衍生文件。
